# MyChurch POS (Церковная лавка)

**Язык:** [English](README.md) | Русский

Веб-система учёта и рабочего места кассира (POS) для церковной лавки, построенная на Django. Приложение объединяет в едином журнале учёт продаж товаров и свечей, приём пожертвований и записок, кассовые движения, выплаты сотрудникам прихода и формирование отчётов с сохранением снимков и экспортом в PDF.

---

## ✨ Основные возможности

* **Единый реестр номенклатуры (`/directory/`):**
  * Гибкая структура категорий (`ItemType`) и позиций (`Item`) с поддержкой фиксированной цены, свободной суммы по запросу (`0` / `None`) и свободно дополняемых списков (`is_open_list`).
  * Предустановленные категории прихода: **Записки** (`treby-2`), **Свечи** (`candle`), **Таинства** (`treby-1`), **Пожертвования** (`donate`), **Освящение** (`treby-3`), **Люди / выплаты за богослужения** (`staff`), **Деньги / касса и сверки** (`money`), **Прочие требы** (`other-treby`) и **Прочие расходы** (`other-expense`).
  * Гранулярные права на изменение цен (`change_item_price`) и защита системных дескрипторов (`handle`).
* **Журнал транзакций и касса (`/transactions/`):**
  * Учёт операций с привязкой к кассиру, дате/времени, количеству и итоговой сумме (`total_cost`).
  * **Мягкое удаление (`delete_soft`):** удалённые записи помечаются флагом `is_deleted` и скрываются из стандартных выборок (`TransactionManager`), но сохраняются в базе для контроля (`all_with_deleted`).
  * **Аудит операций:** поддержка проверки транзакций аудитором (`is_verified`, `verified_by`) и разграничения прав доступа (`view_all_transactions`, `verify_transaction`).
* **Отчётность и печать (`/reports/`):**
  * Формирование **Кассового отчёта** (`cash-report`) и **Товарной ведомости** (`product-report`).
  * Сохранение каждого сформированного отчёта в базе в виде неизменяемого HTML-дампа (`Report.dump`) с фиксацией автора и времени создания, а также генерация PDF через **WeasyPrint**.
* **Управление доступом и администрирование:**
  * Регистрация (`/register/`), вход (`/login/`), смена пароля (`/password-change/`) и административный интерфейс (`/admin/` - «Управление приходом и торговлей»).
  * Визуальная индикация тестового контура через переменную `TEST_ENVIRONMENT`.
* **Автоматический HTTPS (HTTP-01 и DNS-01):**
  * Встроенный стек `nginx-proxy` автоматически выпускает и продлевает SSL-сертификаты Let's Encrypt через стандартную проверку `http-01` или через Dynu API (`dns-01`), если 80-й порт закрыт.

## 🛠️ Технологический стек

* **Backend:** Python, Django 6.1.2, Gunicorn (5 воркеров)
* **Статика и PDF:** WhiteNoise 6.12.0, WeasyPrint 70.0
* **База данных:** SQLite (персистентное хранилище на хосте в `./db_volume`)
* **Инфраструктура и SSL:** Docker, Docker Compose, `nginxproxy/nginx-proxy:1.6.0`, `nginxproxy/acme-companion:2.4.0` / `acme.sh` (Dynu DNS-01)

## 🚀 Развёртывание в Docker (Production)

### 1. Клонирование репозитория
```bash
git clone https://://github.com.git
cd mychurch_pos
```

### 2. Настройка `.env`
Скопируйте шаблон переменных окружения и заполните обязательные параметры:
```bash
cp .env.example .env
```

Основные переменные в `.env`:

| Переменная | Обязательна | Описание |
| :--- | :--- | :--- |
| `DOMAIN` | Да | Доменное имя сервера (например, `://example.com`). |
| `LETSENCRYPT_EMAIL` | Да | Email для уведомлений Let's Encrypt при выпуске SSL. |
| `DJANGO_SECRET_KEY` | Да | Уникальный секретный ключ Django. |
| `DJANGO_SUPERUSER_USERNAME` | Да | Логин начального администратора (создаётся при первом запуске). |
| `DJANGO_SUPERUSER_EMAIL` | Да | Email начального администратора. |
| `DJANGO_SUPERUSER_PASSWORD` | Да | Пароль начального администратора (существующий пароль не перезаписывается). |
| `DROPBOX_APP_KEY` | Да | Ключ приложения Dropbox для `docscanner`. |
| `DROPBOX_APP_SECRET` | Да | Секрет приложения и ключ проверки подписи webhook. |
| `DROPBOX_REFRESH_TOKEN` | Да | Токен обновления OAuth2 Dropbox. |
| `TIME_ZONE` | Нет | Часовой пояс (по умолчанию `Asia/Novokuznetsk`). |
| `TEST_ENVIRONMENT` | Нет | `true` / `false` - визуальная пометка тестового окружения. |
| `DYNU_CLIENT_ID` | Нет | Client ID от Dynu API (включает профиль `dns-01` при заполнении вместе с секретом). |
| `DYNU_CLIENT_SECRET` | Нет | Secret от Dynu API для проверки домена по DNS-01. |

### 3. Запуск стека
Запустите приложение с помощью `start-compose.sh`:
```bash
chmod +x start-compose.sh
./start-compose.sh
```

Скрипт `start-compose.sh` автоматически проверяет наличие `DYNU_CLIENT_ID` и `DYNU_CLIENT_SECRET` в `.env`:
* Если оба параметра заданы, запускается профиль **`dns-01`** (контейнер `acme-dynu`).
* Если параметры пустые, запускается профиль **`http-01`** (контейнер `letsencrypt`).

При старте контейнер `web` автоматически выполняет:
1. `python manage.py migrate` - применение миграций базы данных.
2. `python scripts/data_upload.py` - загрузку базовых категорий, номенклатуры и типов отчётов.
3. `python scripts/ensure_superuser.py` - создание учётной записи администратора.
4. Запуск `gunicorn` на порту `8000` за обратным прокси `nginx-proxy` (порты `80` и `443` с редиректом на HTTPS).

## 💻 Локальный запуск для разработки

1. Создайте виртуальное окружение и установите зависимости (для работы WeasyPrint в системе должны быть установлены библиотеки Pango/Cairo):
   ```bash
   python3 -m venv venv
   source venv/bin/activate
   pip install -r web/requirements.txt
   ```
2. Примените миграции, загрузите начальные справочники и запустите сервер разработки:
   ```bash
   python web/manage.py migrate
   python web/scripts/data_upload.py
   python web/manage.py runserver
   ```
   Go-сервис синхронизации запускается отдельно: `cd services/docscanner && go run main.go`.

## 💾 Резервное копирование

База данных SQLite сохраняется на хосте в директории `./db_volume`. Для настройки регулярного резервного копирования используйте шаблон `db_backup.sh.example`:
```bash
cp db_backup.sh.example db_backup.sh
chmod +x db_backup.sh
```
